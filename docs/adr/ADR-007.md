# ADR-007: Desktop IPC Architecture

**Status:** Accepted

**Date:** 2026-07-19

## Context

The Electron renderer process must be isolated from Node.js and Electron APIs as a security best practice (Electron's recommended security model). However, the application needs to communicate with the main process for backend proxy calls, system operations, file access, and license management. Without a structured IPC boundary, the renderer would have unrestricted access to Node.js APIs, increasing the attack surface and making the app vulnerable to remote code execution if a renderer compromise occurs. The admin session token must never be exposed to the renderer process.

## Decision

We adopt the **contextBridge pattern** with `ipcRenderer.invoke` / `ipcMain.handle` for all renderer-to-main communication. A preload script exposes a typed `EscalaDesktopBridge` interface via `contextBridge.exposeInMainWorld`. The main process validates every IPC sender origin using `assertTrustedIpcSender()`. Content Security Policy (CSP) is enforced in production builds.

### Architecture Overview

```

│  ┌───────────────────────────────────┐  │
│  │  React SPA                       │  │

│  └──────────┬────────────────────────┘  │
│             │ contextBridge             │
├─────────────┼───────────────────────────┤
│  Preload Script                         │
│  ipcRenderer.invoke(channel, ...args)  │
├─────────────┼───────────────────────────┤
│  Main Process                           │
│  ipcMain.handle(channel, handler)      │

```

```typescript

  app: {
    getVersion(): Promise<string>
    getPlatform(): Promise<string>
    getStoreValue(key: string): Promise<unknown>

  github: {
    startDeviceFlow(): Promise<DeviceFlowResponse>

    getAuthorizedUser(): Promise<GitHubUser | null>

    getInstallationToken(installationId: number): Promise<string>

  technical: {
    startLocalServer(port: number): Promise<void>
```

### Sender Validation

Every IPC handler calls `assertTrustedIpcSender(event)` before processing:

```typescript
function assertTrustedIpcSender(event: IpcMainInvokeEvent): void {
  const senderUrl = event.sender.getURL()
  if (!senderUrl.startsWith('file://')) {
    throw new Error('Untrusted IPC sender: non-file origin')
  }
  if (event.senderFrame && !event.senderFrame.url.startsWith('file://')) {
    throw new Error('Untrusted IPC sender frame')
  }
}
```

### Back-End Proxy Pattern

The main process acts as a proxy between the renderer and the local backend server (localhost:8087). The renderer never makes direct HTTP requests to the backend; all calls go through IPC channels. This ensures:

- The admin session token (stored in main process memory) is never exposed to renderer
- Request validation and rate limiting happen in the main process
- The renderer operates with zero Node.js/Electron API access

### Content Security Policy

Production builds enforce strict CSP:

```
default-src 'self';
script-src 'self';
style-src 'self' 'unsafe-inline';
img-src 'self' data:;
connect-src 'none';
font-src 'self';
object-src 'none';
frame-src 'none';
```

`connect-src 'none'` prevents any direct network requests from the renderer, forcing all HTTP through the main process IPC proxy.

## Consequences

### Benefits

- **Security:** Renderer has zero access to Node.js APIs; CSP blocks direct network requests; admin token never exposed to renderer
- **Type safety:** `EscalaDesktopBridge` interface provides compile-time type checking across the IPC boundary
- **Auditability:** All IPC calls are centralized through `ipcMain.handle`, making them easy to log and audit
- **Testability:** The bridge interface can be mocked for renderer-side unit tests
- **Compliance:** Follows Electron security best practices (contextBridge, IPC validation, CSP)

### Risks

- **Boilerplate:** 27 IPC channels require corresponding preload definitions, main process handlers, and type definitions — mitigated by code generation from the shared interface
- **Debugging complexity:** IPC issues span two processes — mitigated by structured logging in `assertTrustedIpcSender` and channel-level tracing
- **Latency:** Every operation crosses the IPC boundary — acceptable for UI-initiated actions; bulk operations batch through dedicated channels

### Trade-offs

- We accept the boilerplate overhead of 27 channel definitions in exchange for a fully isolated renderer
- We accept the IPC latency in exchange for the security boundary between renderer and main process
- We accept `connect-src 'none'` restrictions in exchange for guaranteeing all network traffic flows through auditable main process handlers
