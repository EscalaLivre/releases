# ADR-010 — GitLab CI/Registry e GitHub releases publicas

## Status

Aceito.

## Contexto

O projeto Escala Livre utiliza GitHub como plataforma principal. Durante a auditoria
pre-plano, o GitHub apresentou incidente de API Requests Partial Outage e Actions
Degraded Performance, tornando CI e publicacao de releases indisponiveis.

O GitLab foi configurado como plataforma alternativa com:
- CI/CD pipelines
- Container Registry
- Artefatos de build
- Releases privadas (QA)
- Armazenamento de fallback para releases publicas

## Decisao

```
GitHub:
  → repositorio historico principal
  → Device Flow (OAuth)
  → releases publicas do Client Electron
  → mirror do codigo

GitLab:
  → CI/CD pipelines
  → Container Registry
  → artefatos privados de build
  → releases privadas (QA e pre-release)
  → fallback operacional quando GitHub estiver degradado
  → Generic Package para fallback de assets
```

## Consequencias

Positivas:
- Independencia de unico provedor
- Continuidade operacional durante incidentes GitHub
- CI paralela para validacao cruzada

Negativas:
- Duas plataformas para gerenciar
- Tokens e permissoes duplicados
- Sincronizacao manual ate ADR-011 ser revisado

## Notas

O updater publico do Client Electron continua apontando exclusivamente para
GitHub ate que um contrato formal de provider com fallback seja implementado
e testado (previsto em sprint futura).
