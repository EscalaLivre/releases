# ADR-011 — Estrategia de mirror GitHub/GitLab

## Status

Aceito.

## Contexto

Com dois provedores de repositorio (GitHub e GitLab), e necessario definir
a estrategia de sincronizacao entre eles para evitar divergencia, loops
de mirror automatico, e conflitos de history.

## Decisao

```
Proibido mirror automatico circular:
  GitHub → GitLab → GitHub

Proibido mirror automatico bidirecional.

Politica durante a transicao:
  push explicito para GitHub
  +
  push explicito para GitLab

O agente/desenvolvedor e responsavel por executar ambos os pushes.
```

## Politica de fallback durante incidente

Se GitHub estiver degradado:
- push apenas para GitLab
- CI no GitLab
- artefatos no GitLab
- releases privadas no GitLab
- preservar o push para GitHub para quando o servico recuperar

Se GitLab estiver degradado:
- push apenas para GitHub
- CI no GitHub Actions (se operacional)
- releases no GitHub

## Revisao

Apos duas sprints estaveis, reavaliar esta decisao e produzir ADR
complementar definindo se GitLab passa a ser o remoto primario dos
repositorios privados.

## Consequencias

Positivas:
- Sem risco de loop de mirror automatico
- Controle explicito sobre cada push
- Simplicidade operacional durante a transicao

Negativas:
- Carga manual adicional (dois pushes por commit)
- Risco de esquecer um dos provedores
- Divergencia temporaria se um push falhar

## Gatilho para revisao

- Duas sprints concluidas sem incidente de sincronizacao
- Ou um incidente de divergencia entre GitHub e GitLab
