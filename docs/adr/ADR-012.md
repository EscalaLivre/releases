# ADR-012: Estrategia de Transicao SQLite para MySQL

## Status

Accepted

## Date

2026-07-20

## Context

The Escala Livre backend currently uses SQLite as its local persistence engine during the pre-server (desktop) phase. The planned server deployment requires MySQL as the production database for multi-user, multi-instance scenarios. Several critical constraints apply:

1. Existing installations must not lose data during transition
2. Local-first (desktop) users must continue working offline even after MySQL support is added
3. Schema must be compatible with both engines during transition
4. Rollback must be possible without data loss

## Decision (concrete rules)

1. SQLite remains the default and sole engine during desktop/local phase
2. A parallel `mysql` Spring profile is introduced with MySQL-specific datasource config and Flyway migrations
3. No automatic destructive migration — conversion from SQLite to MySQL must be an explicit, user-initiated, documented operation
4. Testcontainers MySQL is used in CI and integration tests for the MySQL profile
5. Flyway continues managing schema for both engines; MySQL migrations are versioned after the current SQLite V8
6. Rollback: a documented manual procedure exists to revert from MySQL to SQLite using backup/restore
7. Removal of SQLite as default is a separate future ADR, not part of this transition

## Consequences

- Dual Flyway migration sets to maintain
- Testcontainers adds test dependency but ensures MySQL compatibility without external DB
- SQLite-to-MySQL conversion tooling must be built/tested before server deployment
- Transition is explicit and reversible, reducing risk during cutover
